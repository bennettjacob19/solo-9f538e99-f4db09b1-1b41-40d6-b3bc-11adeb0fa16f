# 检查点重分片网页（训练机换卡）

训练机换卡后，检查点要交给不同数量的 rank。本应用用 **Flask + NumPy** 实现重分片：
旧卷上的检查点按 rank 存放（参数 `param`、同段的 Adam 一阶 `adam_m` / 二阶 `adam_v`
状态和训练步 `step`），重分片时把各 rank 的数组按 rank 顺序拼成全局数组，
**三个数组按同一套全局下标连续等分，余数依次分给低 rank，每片都带训练步**，
按新 rank 数写到新卷并提供 NumPy 文件下载。

读写全程流式：单个源片或新片**超过 16 MiB 也能在网页上完成重分片**。源 NPZ
支持 `np.savez`（未压缩）与 `np.savez_compressed`（压缩）两种；压缩源只解压一次，
磁盘上不产生解压副本。

## 运行

### Docker Compose（推荐）

```bash
docker compose up --build
# 打开 http://localhost:8000
```

数据持久化在命名卷 `reshard-data`（容器内 `/data`）。

### 本地运行

```bash
pip install -r app/requirements.txt
python3 app/server.py          # 数据目录默认 ./data，可用 DATA_DIR 覆盖
```

### 自测

```bash
python3 tests/selftest.py      # 20 项，全部通过退出码为 0
```

## 网页操作

1. **旧卷状态**：内置样例检查点（正常 3 rank 未压缩 / 2 rank 压缩源 / 训练步不一致 / 缺片）。
   可**模拟卸载**、**挂回同一卷**、**挂载不同卷**（演示卷 ID 不符不恢复可读性）。
2. **重分片**：选检查点，填**新 rank 数**和**新卷容量（字节）**，勾选
   **续训时能否挂旧卷**（勾选则发布结果依赖旧卷）；另有"模拟写失败"开关用于演示。
3. **新卷与当前发布**：显示容量、当前占用（发布 + 暂存）、**分片文件占用峰值**
   （上一套和本次暂存都计入）、**本次实际读取的源数组正文字节数**、发布记录与可读性，
   按新 rank 下载 npz。
4. **操作历史**：每次重分片的结果、失败原因与读源正文的字节数。

## 内存与读取量约束

- **内存有界**：从读源到回读校验完毕，内存中同时驻留的数组正文合计 **≤ 16 MiB**。
  实现上按 1 MiB 块流式读源、流式写新片、流式回读，单条流只驻留一块；
  三个数组各一条流，回读时另有源与暂存两条流。整个流程不把数组整块载入。
- **读源正文 ≤ 2 倍**：写新片时每个数组读 1 遍，回读校验时再读 1 遍，合计 **正好 2 倍**
  源数组正文；重复解压（压缩源被读两轮）也计入这个字节数。文件头预读与 `step`
  标量不计入正文统计。
- **磁盘上不另存解压副本**：压缩源直接用 `zipfile` 流式解压到新片，源目录不发生成任何临时文件。
- **回读核对**：写齐后回读整套暂存 NPZ，逐片按全局下标与源检查点核对
  `param` / `adam_m` / `adam_v` 三个数组的值和训练步。
- **失败语义**：源片读坏（损坏 / 截断 / CRC 错）、写入失败、回读不符时，
  清掉本次暂存、**保留上次发布**，并在历史里记录原因。
- **网页显示**：页面与操作历史显示本次实际读取的源数组正文字节数
  （`source_body_bytes_read`）。

## 发布与失败语义

- 读源前要求旧卷可读（已挂载且为同一卷）；源校验**缺片**、**训练步不一致**直接失败。
- **逐片写入暂存区**，**上一套发布 + 本次暂存一起计入容量**，超限即失败。
- 全套暂存分片在**指定挂载条件下回读校验**（存在性、训练步、长度、与源拼接一致、
  逐字节比对）才发布；回读期间旧卷失去可读性同样失败。
- **缺片、训练步不一致、源片读坏、超额、写失败、模拟写失败、回读不符**时：
  清理暂存、**保留上次发布结果**、历史记录原因。
- 发布时若声明"续训可挂旧卷"，结果标记为依赖旧卷：**旧卷卸载后标为不可读，
  挂回同一卷（卷 ID 相同）后恢复**；挂不同的卷不恢复。不依赖旧卷的结果不受卸载影响。

## 已实现

- 按 rank 存参数 + 同段 Adam 一阶/二阶状态 + 训练步的旧卷样例（含压缩源、缺片、训练步不一致样例）
- 三个数组同一全局下标连续等分、余数给低 rank、每片带训练步
- 选检查点 + 新 rank 数 + 新卷容量（字节）+ 续训能否挂旧卷
- 模拟卸载 / 挂回同一卷 / 挂载不同卷；依赖旧卷的结果卸载后不可读、挂回同一卷恢复
- 新卷占用与峰值展示（上一套 + 本次暂存计入容量）；按新 rank 下载 npz
- 流式重分片：压缩 / 未压缩源均可读，单源片与新片可超过 16 MiB
- 内存中同时驻留数组正文 ≤ 16 MiB；源正文读取量正好 2 倍；无解压副本
- 全套在指定挂载条件下回读可读才发布；七类失败保留上次发布并记录原因
- 页面显示本次实际读取的源数组正文字节数
- Docker Compose 一键启动

## 已验证（本环境实测）

- `tests/selftest.py` 20/20 通过：等分规则、3→5 / 3→2 / 30→7 换卡拼接一致、
  四类原有失败保留旧发布且清理暂存、峰值 = 上一套 + 本次暂存、
  卸载→不可读→挂不同卷不恢复→挂回同一卷恢复、不依赖旧卷的结果卸载后仍可读
- 压缩源与未压缩源结果逐字节一致；2 个 rank × 3 数组 × 220 万元素（正文 52.8 MiB、
  新片文件 > 16 MiB）走完重分片与逐片核对
- `tracemalloc` 实测：处理 206 MiB 正文明细时内存峰值约 4.4 MiB（≤ 16 MiB），
  读源正文 bytes = 2 × 正文
- 源片损坏 / 截断 / 真实写 IO 错误 / 暂存被篡改四类失败：暂存清零、上次发布保留
- 真实 HTTP 冒烟：`POST /reshard`、按 rank 下载（内容核对到全局下标 [12,18) 与 step=42000）、
  卸载后下载返回 409、挂回同一卷恢复 200、页面显示读源正文字节数
- `docker-compose.yml` 通过 YAML 解析与关键字段校验

## 未完成 / 限制

- 本环境无 Docker 守护进程，**镜像构建与 `docker compose up` 未实际执行**，仅静态校验
- 卷为本地目录模拟，非真实挂载点；挂载状态存于 `mount.json`
- 单进程串行（锁保护），无任务队列与并发重分片
- 源仅支持一维数值数组；多维 C 连续数组按扁平一维处理（新片一维输出），
  对象数组被拒绝
- 回读校验靠流式字节比对（含 zip CRC），未另存逐片 sha256 校验和文件
